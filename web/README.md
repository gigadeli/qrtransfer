# QRTransfer Web 版（受信ページ・送信ページ）

- 受信ページ（`index.html`）: iPhone / Android のブラウザで、QRTransfer が表示する QR を読み取ってファイルを受信します。
  公開先: https://gigadeli.github.io/qrtransfer/
- 送信ページ（`send.html`）: パソコン（スマホでも可）のブラウザで、ファイルを QR にして全画面に表示します。
  公開先: https://gigadeli.github.io/qrtransfer/send.html

## 受信ページ

- デスクトップ版と同じプロトコル（`src/qrtransfer/protocol.py`）・同じ照合（SHA-256）で受信します。
- 送信側が「修復用 QR を混ぜる」方式なら、取りこぼしがあっても読み続けるだけで完了します（欠落番号の入力は不要）。
- 受信したファイルが画像・動画・音声・テキストなら、受信完了の画面でそのまま確認できます（`src/lib/preview.ts`）。
  HTML・SVG など、ブラウザがページとして開いて中のスクリプトを動かし得る種類は表示しません。端末のブラウザが対応していない形式（例: 一部の動画コーデック）は表示されません。
  動画・音声は、iPhone の Safari でも再生できるように、Service Worker 経由の URL（範囲指定に対応）で渡します（`src/lib/media.ts`・`scripts/sw.js`）。
  データはブラウザのキャッシュに一時的に置き、表示を閉じたときとページを開き直したときに消します。
- 送信側が QR を複数並べて表示しているときは、1 回の撮影で全部読みます（最大 8 個）。読む範囲（ROI）は、読めた QR 全体を囲むように決めます（`src/lib/roi.ts`）。
  読めなかった QR のシャープ化による読み直しは 1 回の撮影につき 1 つまでにしています（全部を読み直すと読み取り回数が落ち、次の表示を取りこぼすため）。
- 「取りこぼし」: 送信側は QR を決まった順に表示するので、直近 5 秒に読めた QR の番号の範囲と実際に読めた数から、読めずに流れていった割合を推定して表示します（`src/lib/loss.ts`）。
  30% を超えると、送信側の表示速度か同時に表示する QR の数を下げるよう案内します。
- 「進捗を映像に表示」（既定で ON。この端末のブラウザに覚えます）: カメラの映像の上端に、受信率・チャンク数（修復中は集めた式の数）・残り時間・取りこぼしを重ねて表示します。
  スクロールせずに確認でき、スマホを動かさずに済みます（表示するだけで、QR の読み取りには影響しません）。
- すべてのチャンクがそろって照合を始めた時点で、カメラを自動で止めます（読み取りの処理も止まり、照合が速く終わります）。
  「次の受信へ」を押すと、カメラをもう一度起動して次の転送を待ちます。
- 見た目は Liquid Glass 風（色のにじんだ背景に、半透明でぼかしたガラスの面を重ねる）です。ライブラリは使わず CSS だけで描いています。
  ぼかしが使えないブラウザや、端末で「透明度を下げる」を設定している場合は不透明な面で表示します。
  カメラの動作中はぼかしをすべて止め、少し不透明な面に切り替えます（ぼかしの描き直しが映像の取り込みや読み取りと取り合い、読み取り回数が下がるため）。
- 修復用 QR を受け取っている間は、「修復」の行に集めた式の数と必要な数（欠けたチャンクの数）を表示します。受信率のバーでは、式の分を斜線で示します。
- カメラの撮り方（この端末のブラウザに覚えます）:
  - **高解像度（1920×1080）**（既定）: QR を複数並べたときや、離れて撮るとき向け。iPhone では 30fps になります。
  - **高速（1280×720・60fps）**: 撮影 1 枚の時間が短く、QR の切り替わりが混ざった画像が減ります。1 マスが粗くなるので、QR を複数並べるときは高解像度がおすすめです。
    iOS は 60fps を「希望」として頼むと 30fps にするので「必須」として頼み、応じられないカメラでは希望として頼み直します。
  画面下部に、カメラが実際に出している解像度と fps を表示します。
- 読み取りは CPU のコアが 4 つ以上の端末では 2 つのスレッドで並列に行い、空いている方に新しい映像を渡します（1 秒あたりの読み取り回数が約 1.7 倍）。
- フォルダ（bundle）は ZIP にまとめ直して保存します（iPhone の「ファイル」アプリでタップすると展開できます）。
- QR の読み取りは zxing-cpp の WebAssembly 版（デスクトップ版と同じ部品）。読めないときは QR の周辺をシャープ化して読み直します。
- 受信中のデータはブラウザのメモリ上にだけ持ちます（ページを閉じると消えます）。受信できるのは 100MB まで（転送量・伸長後とも）で、超える転送は受け付けずにお知らせを出します。実用的には数 MB までが目安です。
- 悪意のある QR への対策: フレームが名乗る総チャンク数・サイズは確保前に上限で確かめ、伸長は META の値を超えた時点で打ち切ります。保存（ダウンロード）は常に `application/octet-stream` で行い、受信した HTML などがこのサイトのページとして開かれないようにしています。
- フォルダ内で名前が重なるファイル（大文字と小文字の違い、使えない文字の置き換えなど）は「名前 (2)」のように連番を付けて残します。65,536 個を超えるファイルは ZIP64 で保存します。
- カメラは HTTPS のページでしか使えません。
- 一度開くと、ページと読み取り部品を端末に保存し、以後はオフライン（機内モードなど）でも開いて受信できます。ホーム画面に追加すると、アプリのように全画面で開けます。
  - 仕組み: ビルド時に `vite.config.ts` の `offline()` が、出力したすべてのファイルを保存する Service Worker（`dist/sw.js`、元は `scripts/sw.js`）を書き出します。
  - 更新: 通信できるときはページを開くたびに最新版を読み込み、保存内容も新しい版に入れ替えます（1 つ前の版も念のため残します）。

## 送信ページ

- パソコン版の送信と同じ形式のデータを作ります（梱包・META・フレーム・修復用 QR・表示順。`src/lib/pack.ts`・`src/lib/carousel.ts`）。
  同じ中身からは Python 版とバイト単位で同じフレームになることを、テストで確かめています（`test/send.test.ts`）。
  - 違いは圧縮だけです。ブラウザには xz（lzma）で圧縮する軽い手段がないため、zlib（レベル 9）だけを試します。受信側はどちらも読めます。
  - 送れる大きさは 100 MB まで（Web 版の受信の上限と同じ）。
- 送るもの: ファイルの選択（複数可）、フォルダの選択（パソコンのみ。空のフォルダは含まれません）、ドラッグ＆ドロップ（フォルダは空のフォルダも含む）。
  1 つのファイルはそのまま、フォルダや複数のファイルは tar にまとめます（パソコン版と同じ決まり）。
- 設定（送信方式・表示速度・同時に表示する QR の数・誤り訂正・チャンクサイズ・修復用 QR の割合）は、パソコン版と同じ既定値と上下限です。この端末のブラウザに覚えます。
- QR の生成は `src/lib/qrcode.ts`（バイトモード専用の実装）。全フレームを同じバージョンにそろえ、誤り訂正を勝手に上げないためです。
  容量が Python 版（segno）と全バージョンで一致すること、作った QR を受信側の読み取り部で読み戻せることをテストしています（`test/qrcode.test.ts`）。
  - DATA・修復用フレームはマスクを固定し（8 種類の評価を省く）、生成を約 6 倍速くしています（v27 で 2.6 ms → 0.4 ms）。
    中身は圧縮済み・XOR 済みでほぼ乱雑なので、どのマスクでも読みやすさはほとんど変わりません。文字（JSON）が並ぶ META だけは規格どおり評価します。
- 表示: 開くと「待機中」で最初の QR（META）を出したまま待ちます。「開始」（Space）で送信を始めます。
  - QR は Web Worker（`src/send/frameWorker.ts`）で少し先まで作っておき、画面の書き換えに合わせて fps の間隔で切り替えます。作るのが間に合わないときは、飛ばさずに待ちます。
    1 周分の QR（1 ビットずつに詰めて 48 MB まで）に収まる転送では、作った QR を全部とっておき、2 周目からは作り直しません。
  - 並べた QR は 1 つずつ時間をずらして切り替えます（`src/send/scheduler.ts`。パソコン版も同じ）。切り替わりの瞬間にかかった撮影で読めなくなるのが 1 つだけで済みます。
  - 1 マスを整数ピクセルでキャンバスに描き、画面に合わせる残りの拡大はブラウザになめらかに任せます。
    半端な倍率でくっきり拡大すると、マスの幅が 1 ピクセルずつばらつき、小さく並べたときに読み取りが落ちるためです。
  - 画面の書き換えが 1 秒以上止まったら（タブを隠した、ウィンドウが隠れたなど）、止まっていたことを画面下に表示します。
  - 操作はパソコン版と同じキーです: Space 開始・一時停止／←→ 一時停止中に 1 枚ずつ／+ − 速さ／C QR の数／R 再送（欠落番号の入力）／F 全画面／Esc 終了。画面下のボタンでも操作できます。
  - 送信中は画面が暗くならないようにします（Wake Lock）。ブラウザのタブを隠すと表示が止まります。

## 開発

```bash
npm install
npm run fixtures   # テスト用データを Python 版の送信処理で作る（リポジトリ直下の .venv か、segno・numpy・pillow・opencv が入った Python）
npm test
npm run dev        # http://localhost:5173/ 。?demo を付けると、カメラの代わりにテスト用の QR を流す（?demo=2 で 2 枚/秒）
npm run build
```

スマホの実機で開発中のページを試すには、カメラのために HTTPS が必要です（`npm run dev` は HTTP）。
GitHub Pages に公開されたページで確かめるのが簡単です。

## 構成

| ファイル | 内容 |
|---|---|
| `src/lib/protocol.ts` | フレームの解析、欠落番号の表記 |
| `src/lib/meta.ts` | META（ファイル名・サイズ・ハッシュなど）の検証 |
| `src/lib/assembler.ts` | フレームの組み立て、別の転送の検出、完了時の照合と保存用ファイルの作成 |
| `src/lib/repair.ts` | 修復用フレームの復元（Python 版 `repair.py` と同じ決まり） |
| `src/lib/codec.ts` | 伸長（zlib / xz）と SHA-256 |
| `src/lib/archive.ts` | tar の読み取り（危険なパスは除外）と ZIP の作成 |
| `src/lib/qr.ts` | QR の読み取り（zxing-wasm）と画像補正 |
| `src/decodeWorker.ts` | 読み取りを別スレッドで行う Web Worker |
| `src/useScanner.ts` | カメラの取り込み |
| `src/lib/pack.ts` | 送信: 梱包（tar）、圧縮、転送計画、フレームの作成 |
| `src/lib/carousel.ts` | 送信: 表示順、QR のバージョンの決定、並べ方 |
| `src/lib/qrcode.ts` | 送信: QR の生成 |
| `src/send/` | 送信ページ（`SendApp.tsx` 設定、`Player.tsx` QR の表示、`frameWorker.ts` 準備と QR の生成） |
| `scripts/sw.js` | オフライン用の Service Worker（ビルド時に保存するファイルの一覧を書き込む） |
| `test/interop.test.ts` | Python 版で作ったフレーム・QR 画像を受信できるかの確認 |
| `test/send.test.ts` | 送信: Python 版と同じフレームになるか、Web 版の受信で受け取れるか |
| `test/qrcode.test.ts` | 送信: QR の容量が Python 版と一致するか、読み戻せるか |
