# QRTransfer

インターネットや USB が使えない環境で、**画面に表示した QR コード列を Web カメラで読み取る**ことで、
任意のファイル（単一ファイル／複数ファイル／フォルダ）を一方向に転送する Windows アプリです。
受信したデータは、元データの SHA-256 が一致した場合だけ保存します。

- 対象 OS: Windows 10 / 11（64bit）
- 配布形態: `QRTransfer.exe` 単体（実行環境に Python は不要）

## 使い方

### 送信側
1. `QRTransfer.exe` を起動し、「送信」を押す。
2. 「ファイルを選択（複数可）」「フォルダを選択」、またはドラッグ＆ドロップで送るものを選ぶ。
3. チャンクサイズ・ECC・fps と「QR の表示方法」（全画面／ウィンドウ）を確認して「送信開始」。
   準備（梱包 → 圧縮 → QR 生成）が終わると QR の表示が始まる。
   - **全画面**: 読み取りやすさは最良。メインウィンドウがあるモニタに表示されます（別モニタに出したい場合は、先にウィンドウを移動してください）。
   - **ウィンドウ**: 送信中に他の作業ができます。「常に手前に表示する」を ON にすると、他のウィンドウの後ろに隠れません。
     ウィンドウは自由に動かせ、大きさも変えられます（QR はウィンドウに合わせて最大の大きさで表示されます）。
     位置と大きさ、および表示方法は次回にも引き継がれます。
   - 表示方法は、送信中に `F` キーでいつでも切り替えられます。
   - **開始のタイミング**（既定: 待機する）: QR の表示は「待機中」の状態で開き、最初の QR（メタ情報）を静止表示します。
     受信側はこの QR を映しながらカメラの位置やピントを合わせられます（ファイル名も受信側に表示されます）。
     準備ができたら `Space` / `Enter`（またはダブルクリック）で送信を始めます。
     チェックを外すと、従来どおり表示と同時に送信が始まります。
4. QR 表示中のキー操作

| キー | 動作 |
|---|---|
| `Space` / `Enter` | 待機中: 送信開始 |
| `Space` | 送信中: 一時停止／再開 |
| `←` / `→` | 一時停止中にコマ送り |
| `+` / `-` | fps を変更 |
| `R` | 再送モード（受信側の欠落番号を入力。空にすると解除） |
| `F`（または `F11`） | 全画面 ⇔ ウィンドウ を切り替え |
| `T` | 常に手前に表示（ウィンドウモードで有効） |
| `Esc` | 終了 |

ウィンドウが小さいと QR のセルも小さくなり、カメラが読み取りにくくなります。読み取りが不安定なときは、
ウィンドウを大きくするか全画面に切り替えてください。

### 受信側
1. 「受信」を押し、「カメラを検索」でカメラを選ぶ（解像度 1280×720 / 1920×1080、オートフォーカス）。
2. 保存先を確認して「受信開始」。送信側の画面にカメラを向ける。
   送信側を待機状態（最初の QR を静止表示）にしておくと、QR が映った時点で **ピント・露出の自動調整** が始まります
   （10〜20 秒。下記）。調整が終わってから送信側で Space / Enter を押して送信を始めてください。
3. プレビューの枠が緑なら正常に読めています（赤は読めたが不正なフレーム）。
4. 最後の数枚が埋まらないときは、「欠落番号」をコピー（または読み上げ）して、送信側で `R` を押して入力すると、
   欠落分だけを繰り返し表示します。
5. 完了すると、保存先・サイズ・所要時間・照合結果（OK）が表示されます。

#### ピント・露出の自動調整
読み取り中にオートフォーカスや自動露出が動くと、ピントが迷ったり明るさが揺れたりしてチャンクの欠落が増えます。
そこで受信を始める前に 1 回だけ調整し、良い値に固定します（読み取り中は値を変えません）。
- 「受信開始時に自動調整する」（既定で ON）なら、受信開始後に QR が映ると自動で始まります。
  「ピント・露出を自動調整」ボタンでいつでもやり直せます（調整中に押すと中止し、元の設定に戻します）。
- 手順: ①今の状態（自動）で読み取り成功率とくっきり度を測る → ②オートフォーカスを切り、フォーカス値を 20 刻みで振った後、
  最良値の前後を 5 刻みで詰める → ③自動露出を切り、露光時間（1/8〜1/1024 秒）を振って、白飛びせずコントラストが高く、
  fps も落ちない値を選ぶ → ④固定した状態で、どの画像補正が効くかを調べ、読み取り時に最初に試す。
- 固定した方が悪い項目や、カメラが対応していない項目（値を変えても画像が変わらない）は自動のままにします。
- QR がボケすぎて位置も分からないときは、フォーカスを振りながら QR を探します。
- 結果はカメラ欄の 3 行目に表示され、設定に保存されます。「自動に戻す」でオートフォーカス・自動露出に戻せます。
- 固定したピント・露出は、受信を停止する（カメラを閉じる）ときに自動へ戻します（ドライバに設定が残って
  他のアプリが暗くなる・ボケるのを防ぐため）。次に受信を始めると、保存した値を設定し直します。
- 調整の経過は `%LOCALAPPDATA%\QRTransfer\camera.log` に記録されます。

#### カメラの fps が低いとき
- **接続方式（既定: 自動）**: 受信開始時に、DirectShow（設定順序違いの 2 通り＋形式指定なし）と Media Foundation を
  試して fps を実測し、最も速い方式を使います。選ばれた方式はカメラと解像度ごとに保存され、次回は最初に試します
  （初回は数秒かかります）。カメラ欄の右に、実際の方式・解像度・撮影形式・実測 fps が表示されます。
- 実測が 20fps 未満のときは、画面上部に対処法が表示されます。暗い部屋では露光時間が延びて fps が落ちるカメラがあるため、
  部屋や画面を明るくするのも有効です。
- 各方式の実測結果は `%LOCALAPPDATA%\QRTransfer\camera.log` に記録されます（不具合の調査用）。

#### 読み取りが不安定なとき（ボケ・反射）
- **画像補正（既定で ON）**: 素の画像で読めなかったときだけ、QR の周辺に「シャープ化（弱／強）」
  「2 倍拡大＋適応的二値化」「コントラスト強調＋シャープ化」をかけて再試行します。効いた補正を学習して、次からはそれを先に試します。
  撮影を模した画像での実験では、中程度のボケで読み取り率が 0〜35% から 100% に回復しました。
- **フォーカス**: 画面を撮るとオートフォーカスが迷うカメラがあります。オートフォーカスを OFF にすると
  「フォーカス」スライダーでピントを手動で合わせられます（対応していないカメラもあります）。
  右の「ピント」の値（QR 付近の輪郭のくっきり度合い）が最大になる位置に合わせてください。
- QR は見えているのに読めない状態が続くと、画面上部に対処法が表示されます。
- ボケが強すぎる場合は補正でも読めません。そのときは **送信側でチャンクサイズを小さく**（QR のセルが大きくなる）するか、
  カメラを近づける／解像度を 1920×1080 にするのが効果的です。

途中でアプリを終了しても、受信済みのチャンクは `%LOCALAPPDATA%\QRTransfer\sessions\` に保存されています。
次回起動時に再開するか尋ねます。

### 目安性能（実機で要調整）

| 設定 | fps | 実効速度 | 1MB の転送時間 |
|---|---|---|---|
| 約 600B / ECC M | 5 | 約 3KB/s | 約 6 分 |
| 約 1000B / ECC L | 8 | 約 8KB/s | 約 2〜3 分 |

実用範囲は数 MB までです。

### 設定ファイル
`%APPDATA%\QRTransfer\settings.ini`（カメラのインデックス、解像度、オートフォーカス・手動フォーカス値、固定した露出、受信開始時の自動調整、画像補正、
fps、チャンクサイズ、ECC、保存先、ZIP の自動展開、QR の表示方法・常に手前・ウィンドウの位置と大きさ）

## 利用環境での注意

- Windows の「設定 > プライバシーとセキュリティ > カメラ」で、**「デスクトップアプリがカメラにアクセスできるようにする」を ON** にしてください。
- 署名のない exe は、ウイルス対策ソフトや SmartScreen に誤って検知されることがあります。社内で配布する場合は、コード署名するか除外登録をしてください。
- 画面の QR は撮影されれば誰でも読めます。**機密ファイルは、事前にパスワード付きで暗号化してから送ってください。**
- 利用前に、所属組織の情報セキュリティ規定で使用が許可されているか確認してください。

## 動作確認（セルフテスト）

カメラを使わずに、QR 生成 → 画像化 → zxing-cpp での読み取り → 組立 → SHA-256 照合を行います。

```bat
QRTransfer.exe --selftest
```

結果はダイアログと `%LOCALAPPDATA%\QRTransfer\selftest.log` に出力され、終了コード 0 が成功です（`--quiet` でダイアログを出しません）。

## 開発

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pytest -q
set PYTHONPATH=src
python -m qrtransfer
```

- UI 以外のモジュール（`protocol` / `packer` / `qrgen` / `assembler` / `extractor`）は Qt に依存しません。
- `tests/test_ui_smoke.py` は Qt の offscreen プラットフォームで、送信側の全画面表示をキャプチャして受信側へ流す結合テストです。

### プロトコル v1（概要）

QR 1 枚 = 1 フレーム（ビッグエンディアン）: `magic "QZ"(2) | version(1) | type(1: 0=META,1=DATA) | session_id(4) | seq(4) | total(4) | payload(N) | crc32(4)`

- DATA 20 枚ごとに META（JSON）を 1 枚挟み、無限ループで表示します。
- 全フレームで QR バージョンを統一します（DATA の最大フレームと META が収まる最小のバージョン）。
  チャンクサイズが小さい場合は、META（ハッシュ 2 つを含む JSON）が収まるバージョンが優先されます。

## exe のビルド

PyInstaller はクロスコンパイルできないため、**Windows 上でビルド**します（ネット接続が必要なのは初回の `pip install` だけ）。
できた exe をオフライン環境へ持ち込んでください。

```bat
build.bat
```

- venv の作成 → 依存関係のインストール → `pytest` → `pyinstaller QRTransfer.spec` → **exe 単体のセルフテスト** の順に実行し、
  `dist\QRTransfer.exe`（単体 exe、約 64MB）を作ります。
  内訳はおおよそ OpenCV 31MB / PySide6 18MB / NumPy 9MB です（spec で不要な Qt プラグインや標準ライブラリを除いた後の値）。
- Python 3.12 が見つからない場合は、インストール済みの既定の Python 3 でビルドします。

### 起動が遅い場合（onedir 形式）

単体 exe は起動のたびに一時フォルダへ展開するため、起動に数秒かかります。気になる場合はフォルダ形式でビルドしてください。

```bat
build.bat onedir
```

`dist\QRTransfer\` フォルダごと持ち込み、中の `QRTransfer.exe` を起動します。

`.github/workflows/build.yml` で `windows-latest` 上のビルドとテストを行い、exe を成果物としてアップロードします。
